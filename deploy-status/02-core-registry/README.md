## What was built

- **Permission catalogue** generated by `modules:sync` from the manifests' `resources`
  (`permissions` table): kpcrudy's operations minus `except` plus `extra` for `crud`, `view`
  plus `extra` for `page`, the resource `'name'` override, and `settings.<module>` for every
  module that declares settings. Duplicate names stop the sync before anything is written.
  Permissions no manifest generates any more are reported; `--prune` removes them (and their
  grants) after a y/n confirmation.
- **Default grants** (`group_permissions`), applied once per module on first install, completed
  with `Kpcrudy\Crud::impliedPermissions()` (`edit` → `list`, `show`; `restore` → `trash`…).
  Storage only: Shield's `AuthGroups` and enforcement come in session 07.
- **Settings registry:** manifest settings are registered with their definitions; `setting('News.perPage')`
  returns the manifest default until a value is saved (typed: int, float, bool, json, strings),
  saved values are never overwritten by a sync.
- **Registries** of widgets, scheduled tasks, notification types, menu link types, calendars,
  calendar providers and API resources (declarations only; the services come later). `$api`
  entries must match a route `api/v1/<path>` of the module (D-00-08).
- **`modules:enable` / `modules:disable`:** a disabled module's routes answer 404 and it is hidden
  from the registries and from the enabled permissions, without deleting data or grants. Core
  modules (`Core`, `Auth`, `Users`, `Settings`) cannot be disabled, nor a module enabled modules
  depend on; enabling offers to enable disabled dependencies and runs pending migrations.
- **Demo data:** `DemoData` helper, `demo_records` table, `<Name>DemoSeeder` convention (base
  class `Modules\Core\Demo\DemoSeeder`, stub generated by `make:module`),
  `modules:demo <Name> [--remove|--reload]`, `modules:sync --demo[=A,B]`, `modules:list` shows
  where demo data is loaded. Refused in production unless `Packages.allowDemoInProduction`
  (`Modules\Core\Config\Packages`, overridable by `app/Config/Packages.php` and `.env`).
- **Caches** in scopes (permissions, menus, settings, widgets, assets, modules) with one
  invalidation service.

## How it was built

### Design

`modules:sync` now runs (see "Module lifecycle"):

1. Discover and validate (session 01) **+ build the permission catalogue (duplicates) + check
   `$api` routes**. Any error stops the sync before anything is written.
2. Namespaces file, migrations (packages, then modules), seeders, registry (session 01).
3. **Catalogue upsert** (`PermissionCatalogue::upsert()`): insert new, update changed, report
   stale; `--prune` + confirmation deletes the stale ones and their grants.
4. **Default grants** for each module whose `modules.grants_applied` is 0 (`DefaultGrants::expand()`
   → `PermissionCatalogue::grant()`), then the flag is set: grants the owner removes never come back.
5. **Declarations** (`DeclarationRegistry::build()/store()`): inserted, updated or deleted so the
   table mirrors the manifests.
6. **Caches** invalidated when something changed; then **demo data** with `--demo`.

Runtime reads never load manifests: `ModuleState` (disabled modules), `DeclarationRegistry` and
`SettingsRegistry` read the tables through `CoreCache`. `CoreCache` keeps a version number per
scope in the cache and puts it in every key; `CacheInvalidator` bumps the versions and fires
`modules.cacheInvalidate` for caches kept elsewhere.

`setting()` gets manifest defaults from `ManifestDefaultsHandler`, a read-only handler after the
database handler (`app/Config/Settings.php`); a config class property with the same name keeps
priority (file configuration and `.env` stay the defaults of those settings).

The global filter `moduleenabled` (`app/Config/Filters.php`) maps the matched controller
(`Modules\<Name>\…`) to its module and throws a 404 when it is disabled.

`DemoDataManager::load()` runs the seeder in a transaction (resetting a stale transaction status
first); `remove()` deletes the recorded rows newest first, keeps rows whose delete fails (foreign
keys) and lists them, and deletes recorded files only inside `writable/`.

## Decisions and deviations

Recorded in `docs/decisions.md` as Accepted (proposal); none changes a public convention or
weakens security:

- **D-02-01** One `module_declarations` table for every registry; readers hide disabled modules
  (settings defaults stay readable).
- **D-02-02** Manifest defaults through a read-only Settings handler; config class properties keep
  priority.
- **D-02-03** A global filter maps controllers to modules for the 404 (closure routes cannot be
  mapped; modules use controllers).
- **D-02-04** `modules.grants_applied` flag: default grants applied once.
- **D-02-05** Core resource `modules` (crud with only `list`, plus toggle/sync/upload/uninstall/demo);
  admin gets list/toggle/sync.
- **D-02-06** `DemoSeeder` base class (`load(DemoData)`, `db:seed` refused), console always asks
  y/n, `make:module` generates a demo seeder stub.
- **D-02-07** Cache scopes with version keys; extra scope `modules`.
- **D-02-08** Deviation: enable/disable and demo actions go to the application log until the
  activity log exists (session 12).

Also: `modules:enable` runs pending migrations but cannot publish assets yet (`assets:publish`
arrives with the front-end session 04); Shield's `AuthGroups` are not written yet (session 07).

## How to try it

```bash
bash deploy/setup.sh                  # cloud: MariaDB + composer install
cp env .env                           # CI_ENVIRONMENT = development, database.default.* (MariaDB)
php spark make:module Demo1           # generates Demo1DemoSeeder too
php spark modules:sync                # catalogue, grants, declarations
php spark modules:demo Demo1          # y → demo row in demo1_items
php spark modules:list                # Demo column
php spark modules:demo Demo1 --remove # only the demo rows go
php spark modules:disable Demo1       # http://localhost:8080/backend/demo1 → 404
php spark modules:enable Demo1        # → 403 again (default deny until RBAC)
php spark modules:sync --prune        # lists stale permissions and asks
```

## Known issues

- The 404 of a disabled module relies on the route's controller namespace; a closure route in a
  module's `Routes.php` is not covered (modules use controllers).
- `modules:enable` does not publish assets yet (session 04); activity log entries are application
  log lines until session 12; the demo-data banner and buttons come with the back office
  (sessions 04/29).
- In `.env`, `CI_ENVIRONMENT` overrides a shell variable of the same name (CodeIgniter reads
  `$_ENV` first), so `CI_ENVIRONMENT=production php spark …` does not switch the environment
  when `.env` sets it.
