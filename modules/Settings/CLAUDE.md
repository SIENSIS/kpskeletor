# Settings module

**Purpose:** the settings screens generated from the manifests' `$settings`: one tab per module
(the Core's is "General"), the theme tab, Settings › Security and the actions (test email, clear
caches, publish assets). Values are stored by codeigniter4/settings; only overrides are kept.
Full description: `docs/settings.md`.

## Resources and permissions

- `settings` (single resource, `name => 'settings'`, every CRUD operation excluded): only
  `settings.update` (open every tab, test email, clear caches) and `settings.security`
  (Settings › Security and publish assets, both with the `reauth` filter). Default grant:
  admin `settings.*`.
- Saving a module's tab needs `settings.<module>` (generated by the Core's `CatalogueBuilder`),
  checked in the controller; the theme tab needs `settings.core`. Without it the tab is
  read-only and a POST gets the `can:` filter's 403.
- Menu (`settings` zone): "Settings" (`settings` route) and "Security settings".
- No tables, migrations, demo data, tasks, assets or outbound hosts of its own.

## Main pieces

- `Services/SettingsEditor.php`: tabs, security fields (`group` `security`/`security.<sub>`),
  current value and baseline (file `Config\<Module>` property or manifest default), `save()`
  (skips unchanged, forgets values equal to the baseline).
- `Services/ThemeSettings.php`: `Theme.backend`/`Theme.public` and a theme's options (context
  `theme:<slug>`).
- `Services/SettingsTabs.php`: the tab bar.
- `Forms/Field.php` (type rules, casting, display text), `Forms/FormGenerator.php` (views
  `Views/fields/*`, validation).
- `Controllers/Settings.php` (tabs, saving, logging), `Controllers/Actions.php`.
- Rules that refuse weakening values live in the Core (`Modules\Core\Settings\SecurityRules`),
  registered by its registrar (the 2FA policy is a column of the `groups` table since session 15).
