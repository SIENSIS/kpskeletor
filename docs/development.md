# Development environment

How to install, run and check kpskeletor while developing. Per-computer setup:
`deploy/setup-local.md` (local/XAMPP) and `deploy/setup.sh` (cloud setup script).

## Requirements

- PHP 8.2+ with `curl`, `fileinfo`, `gd`, `intl`, `json`, `mbstring`, `mysqli`, `openssl`,
  `pdo_sqlite`, `sodium`, `sqlite3`, `xml`, `zip`.
- Composer 2, Git.
- MariaDB 10.6+ (or MySQL 8) to run the app; SQLite works too. Tests use SQLite in memory.
- Node.js 20+ and Playwright (only for screenshots and end-to-end tests).

## Install

```bash
composer install
php spark app:install --env=development --db=sqlite --demo   # .env, keys, modules:sync, superadmin, demo data
npm ci                   # optional, Playwright
```

`app:install` asks for the rest (database, superadmin, 2FA); see `docs/commands.md`. By hand
instead: `cp env .env` (set `CI_ENVIRONMENT`, `app.baseURL`, `app.maskKey`, the database),
`php spark key:generate`, `php spark modules:sync --demo`. With an existing `.env`,
`php spark app:install --keep-env` only adds missing keys. To start again, delete `.env`,
`writable/install.lock` and the database (or its tables).

`.env` is never committed. The `env` template defaults to `CI_ENVIRONMENT = production`; set
`development` only on your own computer.

## Serve

```bash
php spark serve          # http://localhost:8080
```

### Apache virtual host (XAMPP)

The document root must be **`public/`**, never the project root (that would expose `.env`,
`writable/` and the source code).

1. `C:\xampp\apache\conf\extra\httpd-vhosts.conf`:

   ```apache
   <VirtualHost *:80>
       ServerName kpskeletor.test
       DocumentRoot "C:/projects/kpskeletor/public"
       <Directory "C:/projects/kpskeletor/public">
           AllowOverride All
           Require all granted
       </Directory>
   </VirtualHost>
   ```

2. Make sure `Include conf/extra/httpd-vhosts.conf` and `LoadModule rewrite_module …` are
   uncommented in `httpd.conf`.
3. Add `127.0.0.1 kpskeletor.test` to `C:\Windows\System32\drivers\etc\hosts` (as administrator).
4. Set `app.baseURL = 'http://kpskeletor.test/'` in `.env` and restart Apache.

`public/.htaccess` already sends every request to `index.php`.

## Checks (run before every commit)

```bash
composer test            # vendor/bin/phpunit (SQLite in memory)
composer analyse         # PHPStan level 6
composer cs              # php-cs-fixer dry run (composer cs-fix to fix)
```

Tests on MariaDB (as CI does): export the `database.tests.*` variables before PHPUnit:

```bash
env database.tests.DBDriver=MySQLi database.tests.hostname=127.0.0.1 \
    database.tests.database=ci4_test database.tests.username=ci4 \
    database.tests.password=ci4 vendor/bin/phpunit
```

### Writing feature tests

Module feature tests extend `Modules\Auth\Tests\AuthTestCase` (or a module base built on it,
e.g. `NewsTestCase`): every namespace migrated, the permission catalogue and default grants as
`modules:sync` leaves them, and requests that carry the session, cookies and a CSRF token. It
provides `createUser()`, `login()`, `loginWith(...$permissions)` (a `user` with only those
permissions, logged in), `send()`, `assertNotFound()` and `assertCrudRefused($response, $listPath)`
(kpcrudy's "not allowed": a redirect to the list with the error message and no success message;
a plain redirect proves nothing, kpcrudy also redirects after a successful write). The module
generated by `make:module` starts with these tests (screen permission, forged POST, migrations
up/down/up).

### End-to-end and accessibility tests

Playwright (`tests/e2e/*.spec.mjs`, configuration `playwright.config.mjs`) opens the public site
as a guest and the main back-office screens as the administrator, in six projects: phone
(390×844), tablet (820×1180) and desktop (1440×900), each in light and dark mode. Every page
fails on:

- a status of 400 or more, or a redirect to the login;
- horizontal overflow (`scrollWidth > clientWidth`);
- a Content-Security-Policy violation reported by the browser (except the development debug
  toolbar's);
- an [axe-core](https://github.com/dequelabs/axe-core) violation of WCAG 2.0/2.1 levels A and AA
  (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`: contrast in both modes, labels, landmarks, names…).
  axe runs through the DevTools protocol, so the page's strict CSP is not weakened.

One more test follows every link of the generated menus at desktop width (status, overflow,
CSP). Screenshots go to `writable/e2e/screenshots/<project>/<screen>.png`.

```bash
npm ci                                   # @playwright/test and axe-core (package-lock.json)
INSTALL_ADMIN_PASSWORD='…' php spark app:install --env=development --url=http://localhost:8089/ \
    --db=sqlite --db-name=e2e.db --email=admin@example.com --demo --2fa=none --no-interaction
php spark modules:enable Tasks && php spark modules:demo Tasks   # the tutorial module's screens (answer y)
E2E_USER=admin@example.com E2E_PASSWORD='…' npm run e2e
npx playwright test --project=phone-dark tests/e2e/public.spec.mjs   # one project or file
```

`npm run e2e` starts `php spark serve --port 8089` (or uses `E2E_BASE_URL`); the administrator
logs in once (`tests/e2e/global-setup.mjs`, the login form is rate limited) and must not use
two-factor authentication. Screens behind `reauth` are left out. A new screen of a module is
added to `tests/e2e/backoffice.spec.mjs` (or `public.spec.mjs`). In the cloud sessions use the
pre-installed Chromium (do not run `playwright install`).

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request:

| Job | What |
|---|---|
| Checks (PHP 8.2, 8.3, 8.4) | `composer validate --strict`, `composer audit`, php-cs-fixer (dry run), PHPStan level 6, PHPUnit on SQLite, `csp:check`, `assets:publish --check` (published copies, manifest and the `vendor.json` checksums of `public/assets/vendor`), a fresh SQLite install with a smoke test |
| Tests on MariaDB (PHP 8.3) | PHPUnit on MariaDB 11.4 and a production install into an empty database |
| End-to-end and accessibility | a demo site on SQLite and `npm run e2e`; screenshots and the HTML report as the `e2e` artifact |
| Secret scanning | gitleaks (release binary checked against its checksums) over the whole history, configuration `.gitleaks.toml` (default rules + an allow-list of test fixtures, CI throwaway passwords, examples and lock files; never allow-list a real secret: remove and rotate it). The e2e job generates its administrator password per run |

Dependabot (`.github/dependabot.yml`) proposes weekly Composer, npm and GitHub Actions updates.

## Notes

- `composer.json` sets `config.platform.php = 8.2.0` so the lock file installs on every
  supported PHP version. Raise it only when dropping PHP 8.2.
- In the cloud sessions the egress proxy may refuse GitHub API zip downloads; `deploy/setup.sh`
  then retries `composer install --prefer-source`. Packages that only ship dists (e.g.
  `phpstan/phpstan`) may need the Composer cache seeded from a git checkout (see
  `deploy-status/00-bootstrap/README.md`).
