# Languages (internationalisation)

The skeleton is complete in **Catalan** (default), **Spanish** (fallback) and **English** (last
resort; the language of the code, comments, documentation and language-file keys). Specification:
"Technical baseline" › "Languages"; built in session 31.

## The language service and the fallback chain

`service('language')` is `Modules\Core\I18n\Language` (overridden in `app/Config/Services.php`).
Every `lang()` call of the modules, the themes, kpcrudy and kpapy goes through it. A line missing
in the requested locale is looked up in:

1. the requested locale (`ca-ES`);
2. the locale without its region (`ca`);
3. `Config\App::$localeFallbacks` in order (`['es', 'en']`);
4. `en` (always last).

CodeIgniter's own class only falls back to English. A key found nowhere is shown as the key.
`Language::chain()` returns the chain and `Language::has($key, $locale)` says whether a locale
defines a line itself (used by the key checks).

Content (pages, news, events) is not a language line: its translations fall back to Catalan, the
required language of content (`Modules\Core\Content\ContentTranslations`, kpapy's default
`localeFallbacks` = the default locale).

## Locales of the site

`Modules\Core\I18n\Locales`:

| | Where | Default |
|---|---|---|
| Supported | `Config\App::$supportedLocales` | `ca`, `es`, `en` |
| Available | setting `Core.locales` (Settings › General, checkboxes, type `multiselect`; at least one; rule `supported_locales`) | every supported locale |
| Default | setting `Core.defaultLocale` (Settings › General) | empty = `Config\App::$defaultLocale` (`ca`); always one of the available locales, else the first available |

`Locales::available()`, `default()`, `isAvailable()`, `name($locale)` (the language's own name,
`Core.locales.<code>`) and `names()`. Before installation (no `.env` nor lock file) only the
configuration is read.

## Negotiation

`Modules\Core\I18n\LocaleNegotiator::negotiate($profileLocale, $acceptLanguage)`: the user's
profile language, then the browser's `Accept-Language` (by quality, `es-ES` matches `es`, `*` and
invalid tags ignored), then the site's default — always among the **available** locales.

- Global filter `locale` (`Modules\Core\Filters\Locale`, before `csrf` and `authsession`, every
  path except `api/*` and `progress/*`): sets the request's and the language service's locale for
  everybody (guests, the login, the web installer).
- `authsession` then applies the logged-in user's profile language when the site offers it.
- `apilocale` (Api module, `api/*`): the same negotiation without a profile.
- The profile form only offers the available locales (`in_list` of them).
- Emails and notifications are rendered in the recipient's language
  (`RecipientLocale::for()`: profile language if available, else the site's default); email
  views set `<html lang>` from the language service.
- `Config\App::$negotiateLocale` stays off (the Core negotiates).

## Language files

- `Language/<locale>/<Name>.php` in every module and theme, with **exactly the same keys** in
  `ca`, `es` and `en` and no empty text.
- CodeIgniter's system texts: Spanish from `codeigniter4/translations`; Catalan copies of the
  files users see in `app/Language/ca/` (`Validation`, `Pager`, `Errors`, `Security`, `Number`,
  `Time`); the other system files (developer messages) follow the chain (Catalan → Spanish).
- Shield's texts (`Auth.*`): Spanish from Shield; Catalan in `app/Language/ca/Auth.php` for the
  keys the Auth module does not define itself.
- kpcrudy and kpapy ship `ca`, `es` and `en`.
- Translated settings (one text per site language): type `translated` (`docs/settings.md`).

## Checks

`tests/unit/I18n/LanguageKeysTest.php` (runs in CI with the rest of the suite):

- same keys in ca/es/en for every module and theme file, no file without its English one, no
  empty text;
- the Catalan copies of the system and Shield files have their keys;
- every literal key used in the code (`lang('Module.key')`) and every key of the manifests
  (resources, permissions, menus, settings, calendars) exists in the three languages;
- widgets, notifications and scheduled tasks have a title in the three languages.

`modules/Core/Tests/I18nTest.php`: the chain, the negotiation, the settings, guests, the profile
and the API.

The tests run with `app.defaultLocale=en` (`phpunit.xml.dist`) because they assert English
texts; the I18n tests set the locales they check.

## Adding a language

1. Add the code to `Config\App::$supportedLocales` and an option to `Core.defaultLocale`.
2. Add `Language/<code>/` files to every module and theme (same keys) and `Core.locales.<code>`.
3. Add Catalan-style copies of the system files if `codeigniter4/translations` has none.
4. Extend `LanguageKeysTest::LOCALES`.
